# Consolidate skills into a single authoritative `skills/` directory

## Goal

There is exactly one authoritative copy of every skill, living in a new
top-level `skills/` directory. `.claude/skills/` and `.cursor/skills/` are
generated by `make install` as symlinks into `skills/`, so the two tools can
never drift again.

## Context

Skills are currently duplicated under `.claude/skills/` (781 tracked files) and
`.cursor/skills/` (830 tracked files). An audit found them inconsistent:

| Skill | State | Authoritative source |
|---|---|---|
| `astro-best-practices` | identical | either (use `.claude`) |
| `book-review` | curly vs straight quotes only | `.claude` (ASCII quotes) |
| `find-artists` | `.claude` ahead: has `reddit_search.py`, PullPush-lag re-fetch, newer data | `.claude` |
| `humanizer` | `.cursor` has correct curly-quote examples + `allowed-tools` | `.cursor` |
| `parse-flowchart` | path-prefix only; `.cursor` has stray `.DS_Store` | `.claude` |
| `svelte-best-practices` | `.cursor` splits content into `references/*.md` and links them | `.cursor` |
| `sync-review-voice` | curly vs straight quotes + path prefix | `.claude` (ASCII quotes) |
| `ship-feature` | only in `.claude` | `.claude` |
| `implement-plan` | only in `.cursor` | `.cursor` |

Also broken today: `.claude/skills/find-artists/SKILL.md` references
`.claude/skills/implement-plan/...`, which does not exist under `.claude`.

### Path-resolution facts that constrain the design

- `find-artists` scripts resolve data via `Path(__file__).parent` — this is
  symlink-transparent and needs no change beyond doc text.
- `implement-plan/scripts/verify.py` computes the repo root with
  `Path(__file__).resolve().parent` then walks **3 levels up**. `.resolve()`
  collapses symlinks, and the canonical `skills/implement-plan` sits **2**
  levels below the repo root, so this must be replaced with an upward search
  for a repo marker (`package.json`).
- `implement-plan` hardcodes repo-root-relative paths in
  `lib/visual.py` (`VISUAL_DIR_REL`), `lib/collections.py` (`NODE_BRIDGE_REL`),
  `lib/runner.py` (`PHASES_DIR_REL`), and a **5-`..`** hop in
  `scripts/visual/playwright.config.ts`. Moving the real files from depth-5
  (`.cursor/skills/implement-plan/scripts/visual`) to depth-4
  (`skills/implement-plan/scripts/visual`) means these become `skills/...` and
  the playwright hop drops to **4 `..`**.
- `.gitignore` has 5 lines hardcoded to `.cursor/skills/implement-plan/...`.

## Design

- Canonical, git-tracked source: `skills/<name>/`.
- `make install_skills` (run by `make install`) removes `.claude/skills` and
  `.cursor/skills` and recreates them as directories of per-skill symlinks:
  `.claude/skills/<name> -> ../../skills/<name>` and the `.cursor` equivalent.
- `.claude/skills/` and `.cursor/skills/` are git-ignored (generated artifacts).
- All in-skill path references use the canonical `skills/<name>/...` form, which
  is valid from the repo root regardless of which tool invoked the skill.

## Tasks

1. **Create `skills/` and move the authoritative copy of each skill** (via
   `git mv`), then `git rm -r` the losing duplicates and the emptied
   `.claude/skills` / `.cursor/skills` trees.
2. **Rewrite path references** `.claude/skills/<x>` and `.cursor/skills/<x>` →
   `skills/<x>` in:
   - `skills/find-artists/SKILL.md`, `.../scripts/sync_covers.py`,
     `.../references/extract-artist-subagent.md` (incl. the absolute
     `Skill directory:` line) and the broken `implement-plan/.../phase_9.py` ref.
   - `skills/parse-flowchart/SKILL.md`, `.../scripts/emit.py`.
   - `skills/sync-review-voice/SKILL.md`.
   - `skills/implement-plan/SKILL.md`, `.../scripts/verify.py` docstring.
3. **Genericize the subagent instruction** in `find-artists` so it names both
   Claude (`subagent_type="general-purpose"`) and Cursor
   (`subagent_type="generalPurpose"`).
4. **Fix `implement-plan` code paths**:
   - `verify.py::_resolve_repo_root` → walk up from `SCRIPT_DIR` to the first
     ancestor containing `package.json`.
   - `VISUAL_DIR_REL`, `NODE_BRIDGE_REL`, `PHASES_DIR_REL` → `skills/...`.
   - `playwright.config.ts` → `../../../../{public,dist}` (4 hops) + comment.
   - `lib/types.py` field comments (cosmetic).
5. **Makefile**: point `IMPLEMENT_PLAN_DIR` at `skills/implement-plan`; add an
   idempotent `install_skills` target; wire it into the `install` aggregate.
6. **`.gitignore`**: repoint the 5 `implement-plan` lines to `skills/...` and add
   `/.claude/skills/` + `/.cursor/skills/`.
7. **Docs**: update the skill-index links in `CLAUDE.md` and the plan-template
   pointer in `docs/plans/README.md` to `skills/...`.

## Verification

- `make install_skills` produces valid symlinks; `ls -l .claude/skills` and
  `.cursor/skills` show every skill pointing into `../../skills/`.
- `python3 -m py_compile` passes on every edited `.py`.
- A standalone check confirms `verify.py::_resolve_repo_root()` returns the repo
  root from the canonical location.
- `rg '\.claude/skills|\.cursor/skills'` returns only intentional matches
  (`.gitignore` ignore lines and the install target).

## ADR

Record in `docs/DECISIONS.md`: single-source skills in `skills/`, projected into
tool-specific dirs via symlinks created by `make install`; in-skill paths use the
canonical `skills/...` prefix so a skill behaves identically under either tool.

## Out of scope

- Rewriting skill prose beyond path fixes and the noted merges.
- Running the full `implement-plan` phase harness (needs the mid-migration Hugo
  tree); correctness of its moved paths is checked structurally, not by a run.
